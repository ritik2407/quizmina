System Objectives

Project Goals

The Quizminia Solution

Quizminia bridges the gap between evaluation and personalization. By incorporating an AI difficulty feedback controller and clean student analytics, the platform maintains a continuous flow zone for the student.

"Keeping students challenged without causing frustration or cognitive fatigue."

  • Adaptive Question Routing: Adjusts difficulty dynamically (0.0 to 1.0) after every answer.
  • High System Availability: Implements a local rule-based safety fallback engine to handle Bedrock API offline states.
  • Intelligent Analytics: Tracks student strengths, weaknesses, and average difficulty baselines.
  • Robust Security Infrastructure: Employs PBKDF2 hashing, AES-256 session cookie encryption, and roles guards.

Database Design & Schema

Database Schema

Relational Entity Layout

The MySQL schema consists of 8 tables structured with strict foreign keys and automated database level cascades:

  • Users & Roles: Separates students, teachers, and admins, storing PBKDF2 hashes and performance baseline profiles.
  • Quizzes & Questions: Base entities containing subject categories, base difficulty scores, and questions.
  • Attempts & Answers: Tracks live attempt indicators, accuracy streaks, response feedback, and custom AI insights.

Core Entities Schema

users: [id, email, password, roleId, firstName, performanceProfile]
quizzes: [id, title, subject, difficulty, timeLimit, createdBy]
questions: [id, quizId, text, options, correctAnswer, difficultyScore]

quiz_attempt_answers: [id, attemptId, questionId, selectedOption, isCorrect]

AI Adaptive Engine & Feedback Loop

AI Adaptation

Real-Time Loop Calibration

Difficulty sits on a float scale from 0.0 (easiest) to 1.0 (hardest). The closed-loop controller behaves as follows:

  • Answer Submission: Student answer triggers streak calculations.
  • AI Inference: The AiService packages history, streaks, and scores, calling Gemma 3 on AWS Bedrock for a new difficulty target.
  • Adaptive Matching: The engine selects the closest unanswered question matching the target difficulty from the database pool.

Rule-Based Safety Fallback Controller

Resilience

High Availability Safeguards

External LLM APIs face latencies, credential expirations, or rate limits. To guarantee uninterrupted test attempts, Quizminia incorporates a local deterministic fallback engine.

If Bedrock fails, the exception is caught, and difficulty scales rules-based according to streak dynamics. 

// Rule-based Fallback Step Math
if (isCorrect) {
  if (correctStreak >= 3) diff += 0.20;
  else if (correctStreak == 2) diff += 0.10;
  else diff += 0.05;
} else {
  if (wrongStreak >= 3) diff -= 0.20;
  else if (wrongStreak == 2) diff -= 0.10;
  else diff -= 0.05;
}
diff = Math.max(0, Math.min(1, diff));
Guarantees zero-downtime test completion on poor network connections.

Security & Session Framework

Security

System Protection Layers

Student data privacy is enforced backend-side. The system implements cryptography models rather than relying on basic text storage:

AES-256-CBC Session Encryption + PBKDF2 SHA-512 Password Verification

  • PBKDF2 Password Hashing: Avoids database exposures by executing 1000 iterations of SHA-512 key stretching with unique salts.
  • AES-256 Cookie Encryption: Session identifiers are encrypted using AES-256-CBC with an initialization vector, decrypted server-side in session middleware.
  • Guards & Middleware: Role-based guards protect specific teacher/admin routes, returning HTTP 403 Forbidden on unauthorized breaches.
